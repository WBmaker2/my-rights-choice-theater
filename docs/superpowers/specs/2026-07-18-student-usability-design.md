# 초등 저학년 실사용 개선 설계

**작성일:** 2026-07-18

**대상 버전:** v0.3.0

**대상 사용자:** 초등학교 1~2학년 학생

**승인한 접근:** B안 — 쉬운 문장과 학생 흐름 집중 개선

## 1. 목표

초등학교 1~2학년 학생이 교사의 추가 설명을 기다리지 않고 화면의 문장과 버튼을 이해하며 활동을 이어 갈 수 있게 합니다. 기존 앱의 핵심 안전 원칙과 5개 장면·8단계 학습 구조는 유지하고, 어려운 표현·긴 선택 목록·잘못 노출되는 조작 요소를 정리합니다.

성공 조건은 다음과 같습니다.

- 학생 화면에서 `가상 인물`, `도움받을 자격`, `책임 있는 어른의 응답`처럼 추상적인 핵심 표현이 쉬운 생활 말로 바뀝니다.
- 시작·안내 화면의 모바일 헤더가 한 줄 안에 정리되고, 실제 활동을 시작한 뒤에만 진행 단계가 보입니다.
- 도움 방법 화면에는 한 번에 4개 이하의 카드만 보입니다.
- `이 장면 건너뛰기`는 장면을 아직 마치지 않은 단계에서만 보입니다.
- 뒤로 가는 버튼은 이동할 화면을 이름으로 알려 줍니다.
- 320px 이상 화면에서 가로 넘침이 없고 모든 주요 터치 요소가 최소 44×44px입니다.

## 2. 지켜야 할 안전 원칙

다음 내용은 표현을 쉽게 바꾸더라도 뜻과 동등한 접근성을 그대로 유지합니다.

- 실제 경험, 이름, 사진, 목소리, 위치를 입력하거나 저장하지 않습니다.
- 모든 장면이 만든 이야기라는 점을 학생에게 분명히 알립니다.
- 말하기, 카드 보여 주기, 문장 가리키기를 똑같이 유효한 도움 요청으로 안내합니다.
- 장면 건너뛰기와 활동 끝내기는 이유 설명 없이 사용할 수 있습니다.
- 한 어른이 돕지 못했을 때 다른 어른에게 다시 알리는 경로를 모든 장면에서 유지합니다.
- 도움을 연결하고 안전하게 지킬 책임이 어른에게 있다는 뜻을 유지합니다.
- 점수, 정답 수, 평가, 학생 책임 전가 표현을 추가하지 않습니다.
- 긴급 도움 안내와 `112` 정보는 바꾸지 않습니다.

## 3. 학생용 문장 설계

### 3.1 공통 원칙

- 한 문장에는 한 가지 행동이나 뜻만 담습니다.
- 한자어나 제도 용어보다 교실에서 자주 듣는 말을 사용합니다.
- 버튼은 행동 결과가 보이도록 `대상 + 행동` 형태로 씁니다.
- 안전 원칙을 지나치게 줄여 뜻이 달라지지 않게 합니다.
- 교사용 안내와 공식 출처 이름은 정확성을 위해 기존 표현을 유지합니다.

### 3.2 확정 문장

| 위치 | 기존 문장 | 바꿀 문장 |
|---|---|---|
| 첫 화면 소개 | 가상 인물의 짧은 장면을 보고, 무엇이 지켜져야 하는지와 여러 도움 방법을 함께 살펴봐요. | 만든 이야기 속 친구를 보며, 친구에게 필요한 것과 도움받는 방법을 찾아봐요. |
| 안내 화면 설명 | 어떤 방법을 골라도 도움받을 자격은 똑같아요. | 어떤 방법을 써도 도움받을 수 있어요. |
| 권리 선택 설명 | 중요한 것은 하나보다 많을 수 있어요. 마음에 닿는 카드를 골라 보세요. | 필요한 것은 여러 개일 수 있어요. 필요하다고 생각하는 카드를 골라 보세요. |
| 권리 카드 | 마음과 이름의 존중 | 내 마음과 이름 지키기 |
| 권리 카드 | 안전하게 보호받기 | 안전하게 도움받기 |
| 도움 방법 설명 | 여러 개를 골라도 되고, 아무것도 고르지 않고 도움 문장으로 가도 돼요. | 여러 개를 골라도 돼요. 바로 도움 문장으로 가도 괜찮아요. |
| 도움 방법 카드 | 자리에서 벗어나기 | 자리에서 나오기 |
| 도움 방법 카드 | 어른에게 함께해 달라고 하기 | 어른에게 도와 달라고 하기 |
| 도움 문장 안내 | 내가 겪은 일을 쓰는 곳이 아니에요. 가상 인물의 문장만 골라요. | 내 이야기를 쓰는 곳이 아니에요. 만든 이야기 속 친구의 문장만 골라요. |
| 문장 미리 보기 | 완성된 도움 문장 | 이렇게 말할 수 있어요 |
| 전달 단계 이름 | 전달 방법 | 어떻게 알려 줄까요? |
| 전달 단계 설명 | 말하기, 카드 보여 주기, 가리키기는 모두 같은 도움 요청이에요. | 말해도, 카드를 보여 줘도, 문장을 가리켜도 도움을 받을 수 있어요. |
| 전달 다음 버튼 | 어른의 응답 보기 | 어른이 어떻게 돕는지 보기 |
| 어른 응답 눈썹말 | 책임 있는 어른의 응답 | 어른은 이렇게 도와야 해요 |
| 어른 응답 제목 | 어른이 듣고 보호해야 해요 | 어른은 듣고 안전하게 도와야 해요 |
| 다른 어른 안내 | 도움을 연결하고 안전하게 지킬 책임은 어른에게 있어요. | 도움받을 때까지 어른들이 함께 도와야 해요. |
| 다른 어른 이전 버튼 | 어른 응답 다시 보기 | 어른이 돕는 방법 다시 보기 |
| 장면 정리 눈썹말 | 점수 없는 장면 정리 | 함께 살펴본 내용 |
| 장면 정리 항목 | 가능한 도움 | 도움받는 방법 |
| 장면 정리 설명 | 듣고, 보호하고, 필요한 도움을 함께 연결하기 | 이야기를 듣고, 안전하게 돕고, 필요한 어른과 함께하기 |

## 4. 기능과 화면 흐름

### 4.1 도움 방법 카드 수

`actions` 화면은 현재 장면의 `actionOptions` 가운데 다음 조건을 모두 만족하는 카드만 표시합니다.

1. `skip-scene`이 아닙니다.
2. `ask-another-adult`가 아닙니다.

따라서 한 장면에 보이는 카드는 `직접 말하기`, `자리에서 벗어나기`, `도움 카드 보여 주기`, `어른에게 함께해 달라고 하기` 가운데 장면에 맞는 최대 4개입니다. `ask-another-adult` 데이터와 각 장면의 `anotherAdult` 문장은 삭제하지 않습니다. 다른 어른 경로는 도움 요청 뒤의 전용 `another` 단계에서 같은 비중으로 안내합니다.

### 4.2 건너뛰기 노출 범위

장면 건너뛰기 막대는 다음 화면에서만 표시합니다.

- `scene`
- `rights`
- `actions`
- `builder`
- `delivery`

`adult`, `another`, `summary`는 이미 도움 문장을 정하고 장면을 마무리하는 단계이므로 건너뛰기 막대를 표시하지 않습니다. 활동 끝내기 버튼은 기존처럼 전체 8개 활동 단계에서 계속 제공합니다.

### 4.3 이전 버튼 이름

- `actions → rights`: `권리 카드 다시 보기`
- `builder → actions`: `도움 방법 다시 보기`

기존 `scene → rights`, `delivery → builder`, `adult → delivery`, `another → adult`, `summary → adult` 버튼은 이미 목적지가 드러나므로 유지하거나 학생용 문장 표에 맞춰 쉬운 말만 적용합니다.

### 4.4 활동 전 헤더

`AppHeader`에 `showProgress` 불리언 속성을 추가합니다.

- `welcome`, `guide`: `showProgress=false`
- 그 밖의 화면: `showProgress=true`

`showProgress=false`일 때 진행 상태 DOM 전체를 렌더링하지 않습니다. 모바일에서는 브랜드 아이콘, `도움이 급할 때` 버튼이 한 줄에 놓입니다. 데스크톱에서는 기존 브랜드 이름도 유지합니다. `활동 끝내기`는 기존 조건대로 활동 화면에서만 표시합니다.

### 4.5 터치 영역

모바일에서 숨겨지는 브랜드 글자와 관계없이 브랜드 링크 자체에 최소 너비와 높이 `44px`을 적용합니다. 다른 버튼의 기존 `48px` 최소 높이는 유지합니다.

## 5. 코드 구조

기존 구조를 유지하며 관련 책임이 있는 파일만 수정합니다.

- `app/content/registry.ts`: 권리·행동 카드 문장과 v0.3.0 업데이트 내역
- `app/theater/TheaterApp.tsx`: 학생용 화면 문장, 카드 필터, 건너뛰기 조건, 구체적인 이동 버튼, 헤더 표시 조건
- `app/components/AppHeader.tsx`: 선택적인 진행 상태 렌더링
- `app/styles/base.css`: 활동 전 모바일 헤더 정렬과 44px 브랜드 터치 영역
- `package.json`, `package-lock.json`: 앱 버전 v0.3.0
- `tests/student-usability.test.tsx`: 이번 개선 사항을 검증하는 새 회귀 테스트

`TheaterApp.tsx`는 현재 414줄입니다. 변경 뒤 500줄에 가까워지면 학생용 문장이나 화면 조건을 별도 모듈로 분리합니다. 이번 변경만으로 500줄 미만이면 관련 흐름을 한눈에 확인할 수 있도록 기존 구조를 유지합니다.

## 6. 상태와 데이터 흐름

새로운 개인정보나 영속 상태는 추가하지 않습니다. 기존 React 로컬 상태와 장면 데이터만 사용합니다.

1. 학생이 화면 버튼을 누릅니다.
2. `screen` 상태가 다음 단계로 바뀝니다.
3. 현재 `screen`으로 진행 표시, 건너뛰기, 화면 문장을 조건부 렌더링합니다.
4. 도움 문장 결과는 기존처럼 브라우저 메모리의 `collected`에만 머물고 새로 고침하면 사라집니다.

헤더 진행 상태를 숨기더라도 장면 진행 계산과 활동 단계 수 `8`은 바꾸지 않습니다.

## 7. 오류와 예외 처리

- 장면 데이터에 `ask-another-adult`가 없더라도 필터는 정상 작동해야 합니다.
- 도움 방법 카드가 0개인 장면이 생기더라도 `도움 문장 만들기` 버튼으로 계속 이동할 수 있어야 합니다.
- 건너뛰기로 마지막 장면을 넘기면 기존처럼 `session`으로 이동합니다.
- 키보드 포커스는 화면 변경 시 새 `h1`으로 이동하는 기존 동작을 유지합니다.
- `showProgress=false`일 때 진행 상태의 접근성 레이블도 DOM에 남기지 않습니다.

## 8. 검증 설계

### 8.1 테스트 우선 회귀 테스트

새 파일 `tests/student-usability.test.tsx`에 다음 행동을 먼저 실패하는 테스트로 추가합니다.

1. 시작 화면에는 쉬운 소개 문장이 보이고 진행 상태는 보이지 않습니다.
2. 안내 화면에는 `어떤 방법을 써도 도움받을 수 있어요`가 보입니다.
3. 권리 화면에는 쉬운 권리 카드 이름이 보입니다.
4. 도움 방법 화면에는 `다른 어른에게 다시 말하기`가 보이지 않고 카드 수가 최대 4개입니다.
5. `actions`와 `builder`의 뒤로가기 버튼은 목적지를 말합니다.
6. `adult`, `another`, `summary` 화면에는 `이 장면 건너뛰기`가 보이지 않습니다.
7. 다른 어른 전용 화면과 문장은 계속 표시됩니다.
8. 업데이트 내역에 `2026-07-18 · v0.3.0`이 표시됩니다.

각 테스트는 구현 전 실패 원인을 확인하고, 최소 구현 뒤 통과를 확인합니다. 기존 테스트는 수정하지 않고 전체 테스트로 회귀를 확인합니다.

### 8.2 정적 검증

- `npm run lint`
- `npm test`
- 변경한 코드 파일이 각각 500줄 미만인지 확인
- `git diff --check`

### 8.3 실제 브라우저 재검증

프로덕션 빌드를 로컬에서 실행하고 375×812, 768×1024, 1280×720에서 다음을 확인합니다.

- 시작부터 장면 정리까지 클릭 흐름이 끊기지 않습니다.
- 모바일 시작·안내 헤더에 큰 빈 둘째 줄이 없습니다.
- 320px 이상에서 가로 스크롤이 없습니다.
- 주요 터치 영역이 44×44px 이상입니다.
- 장면 완료 뒤 건너뛰기가 사라집니다.
- 브라우저 콘솔 오류가 없습니다.
- 개선 전과 같은 화면의 개선 후 스크린샷을 남깁니다.

## 10. 범위 밖

이번 개선에는 다음 작업을 포함하지 않습니다.

- 장면 수를 줄이거나 8단계 구조를 4단계로 합치는 일
- 새로운 장면이나 권리 개념 추가
- 학생 응답 저장, 로그인, 교사용 대시보드 추가
- 긴급 도움 기관 정보 변경
- GitHub 저장소 생성이나 외부 갤러리 등록

## 11. 공개 배포

사용자의 추가 요청에 따라 구현과 검증이 끝난 정확한 소스를 기존 Sites 프로젝트에 새 버전으로 저장하고 공개 배포합니다. 새 Sites 프로젝트를 만들지 않으며 `.openai/hosting.json`의 기존 `project_id`를 재사용합니다. 배포 전 빌드·전체 테스트·린트가 모두 통과해야 하고, 배포 상태가 성공으로 확인된 주소만 결과로 안내합니다.
